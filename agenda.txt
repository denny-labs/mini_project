Phase 1: Data setup & cleaning
1.1 Load data
Load nsei_daily.csv into pandas with Date as datetime index.

Confirm columns: Open, High, Low, Close, Volume.

1.2 Sort and index by date
Sort rows chronologically.

Ensure Date is a proper datetime index (no string dates).

1.3 Check duplicates & missing values
Count duplicate dates and nulls per column.

Decide whether to drop, forward-fill, or leave gaps for non-trading days.

1.4 Validate OHLC logic
Check that Low ≤ Open, Close ≤ High for every row.

Flag/remove rows that violate this.

1.5 Handle outliers (if any)
Inspect extreme values in returns, volume, and price range.

Keep genuine market shocks; only remove clear data errors.

1.6 Create base derived columns
Add Return (daily log or pct change).

Add High_Low_Range = High - Low (or log version).

Add Volume_Change if volume exists.

Phase 2: Feature engineering
2.1 Lag features
Create lagged returns: Return_lag1, Return_lag2, etc.

Create lagged volatility: Vol_lag1, Vol_lag2, etc.

2.2 Rolling volatility features
Compute rolling std of returns over 5, 10, 20 days.

These become both features and the basis for the target.

2.3 Technical indicators
Add moving averages (5, 20, 50 days).

Add RSI (14), MACD, ATR (14) if you want richer features.

2.4 Volume-based features
Rolling mean volume, volume change, volume spikes.

Keep only if they add signal (check correlation later).

2.5 Define target variable
Decide: next-day volatility = rolling std of returns over next N days (e.g., 5).

Ensure no future leakage: features at time t must only use data up to t.

Phase 3: EDA & visualization
3.1 Price trend
Plot Close over time with 20-day and 50-day moving averages.

Identify major trends and turning points.

3.2 Returns distribution
Histogram + boxplot of daily returns.

Check skewness, fat tails, extreme days.

3.3 Volatility over time
Plot rolling volatility (5/10/20-day).

Identify calm vs turbulent periods.

3.4 Volume & range behavior
Plot volume and High–Low range over time.

See if spikes align with volatility spikes.

3.5 Correlations
Correlation heatmap: returns, lags, rolling vol, volume, target.

Identify which features look promising.

3.6 Autocorrelation
ACF of returns and squared returns.

Confirm volatility clustering (squared returns more autocorrelated).

3.7 Regime analysis
Label days as low/medium/high volatility (e.g., by quantiles of rolling vol).

Plot regime over time; note major high-volatility episodes.

Phase 4: Train/test split
4.1 Time-based split
Train: first 70–80% of dates.

Test: last 20–30%.

No shuffling.

4.2 (Optional) Walk-forward validation
Use expanding window: train on [start, t], test on [t+1, t+k], repeat.

Report average metrics across folds.

Phase 5: Model training & comparison
5.1 Baseline models
Persistence: tomorrow’s vol = today’s vol.

Simple linear regression on lagged vol.

5.2 Base paper model
XGBoost Regressor on your feature set.

5.3 Your extensions
LightGBM Regressor.

CatBoost Regressor.

Compare all three.

5.4 Hyperparameter tuning
Use Optuna or RandomizedSearchCV with time-series CV.

Tune: max_depth, learning_rate, n_estimators, subsample, colsample_bytree, regularization.

5.5 Evaluate
Metrics: MAE, RMSE, R².

Directional accuracy: % correct up/down volatility predictions.

Regime-wise MAE/RMSE (low/medium/high vol).
